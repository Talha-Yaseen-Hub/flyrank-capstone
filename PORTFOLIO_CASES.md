## 3. Framed Case Studies (Three Beats)

### Case Study A: The React Priority Planner
*   **The Problem:**
    Professionals face cognitive overload when managing task lists. Traditional planning apps fail to check overdue deadlines relative to local timezones correctly, and many have low-contrast dark-mode themes that make reading difficult in low-light environments.
*   **What I Did (Decisions & Implementation):**
    I built a responsive React dashboard with dynamic stats (including active overdue alerts checking dates at midnight to avoid timezone offsets), inline editing, and category-priority filters. I refactored the AI-generated code to prevent empty title submissions using `.trim()`, structured lazy state initializations for `localStorage` persistence, and manually adjusted dark-mode variables to WCAG AA accessibility contrast ratios.
*   **What Came of It (Outcome):**
    A production-ready frontend task planner that filters data instantly, remembers preferences across browser reloads, and maintains strict contrast states for keyboard and mouse navigation.

---

### Case Study B: The Accessible MVC Settings Form
*   **The Problem:**
    Standard user settings forms generated by quick AI prompts lack keyboard focus traps, fail screen-reader accessibility tests, and rely on disruptive page-refresh errors that disrupt form completion flows.
*   **What I Did (Decisions & Implementation):**
    I implemented a modular MVC-style settings form component in vanilla JavaScript. I hooked up reactive event listeners to give real-time validation feedback on usernames and complex passwords. To satisfy accessibility requirements, I linked error messages to fields using `aria-describedby` and backed the entire component with 16 automated Vitest cases checking boundary limits in JSDOM.
*   **What Came of It (Outcome):**
    A lightweight, framework-free form component that validates inputs reactively, prevents invalid submissions from hitting the database, and achieves a 100% test pass rate.
